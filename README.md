## About

I work the highest tier of technical escalation for the Ignition SCADA platform, where a single production system spans gateways, historians, relational databases, OPC UA servers, virtualized infrastructure, and plant networks that all have to agree before a line can run. My work is root cause analysis under real operational pressure: isolate the failing layer, prove it, ship a fix that holds, and document it so nobody has to rediscover it.

My background runs from the hardware up. An A.A.S. in Industrial and Electrical Technology covered ladder logic, motor controls, drives, and power distribution. A B.S. in Computer Information Systems with a Computer Science minor covered operating systems, systems programming, data structures, networking, and database design. That combination shapes how I debug. I work from the physical and network layers upward rather than starting at the application log, which tends to surface the class of problem that pure software or pure controls engineers both miss.

Day to day I diagnose Python and Java scripting issues, tune gateway and JVM performance, profile slow queries across seven database engines, trace OPC UA and industrial Ethernet traffic, and review system architectures before they turn into incidents. I also mentor the engineers coming up behind me and act as the translation layer between customers and product engineering.
